# Accessibility Instructions — MRPS Agent Toolkit

## Overview
Guidelines for auditing and remediating web accessibility, WCAG 2.1/2.2 AA conformance, ARIA semantics, and keyboard navigation.

## Category & Tools
- **Tools**: `axe-core` (`kind: library`)
- **Category**: `accessibility`

## When to Reach for What
- Reach for `axe-core` to programmatically evaluate DOM structures, check color contrast ratios, verify accessible labels, and audit landmark roles against WCAG 2.2 AA standards.

## The Inspect → Critique → Recommend → Fix Ladder
1. **Inspect**: Run automated accessibility audits via `@axe-core/cli` or Playwright axe integrations.
2. **Critique**: Triage violations based on severity (Critical, Serious, Moderate, Minor) and user impact.
3. **Recommend**: Propose exact semantic HTML replacements, ARIA attributes, or contrast enhancements.
4. **Fix**: Apply accessibility fixes into HTML templates and CSS styles only after user confirmation.

## Tool Guidance: axe-core
### When to use
Use during CI/CD checks, component audits, and pre-release accessibility reviews to detect WCAG compliance issues.
### When NOT to use
Do not use as a substitute for manual screen reader testing (VoiceOver, NVDA) or physical keyboard focus verification.
### Example Invocation
```bash
npx @axe-core/cli https://localhost:8080
```
