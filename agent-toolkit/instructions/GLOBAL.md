# Global Instructions — MRPS Agent Toolkit

## Overview
This document outlines the standard operational protocol and boundaries for coding agents interacting with projects under the MRPS Agent Toolkit guidelines.

## Category & Tools
- **Tools**: `mrps-agent-runner` (`kind: skill`)
- **Category**: `orchestration`

## The Permission Ladder
Always ascend this ladder based strictly on explicit user intent:
1. **Inspect**: Run audit commands, parse files, collect diagnostics. Make zero changes to files.
2. **Critique**: Analyze the audit outputs, contrast against engineering standards, highlight flaws.
3. **Recommend**: Suggest precise code snippets or structural remedies without applying them to disk.
4. **Fix**: Apply targeted changes only after the user explicitly issues a command to fix (e.g., "fix my UI" or "fix sec-01"). Always ask for confirmation before applying file changes.

## Tool Guidance: MRPS Agent Launcher
### When to use
Use whenever the user requests a comprehensive or multi-category project audit (UI, accessibility, security, tests, dependencies, code analysis, or build validation).

### When NOT to use
Do not use for routine single-file edits, quick explanations, or interactive code reviews where full scans are unneeded.

### Example Invocation
```text
Load https://mrps.in/agent-toolkit/runner/SKILL.md as a skill in your agent environment.
```

## Report Format
Audit reports must conform to the standard structure:
```markdown
# <category> — <YYYY-MM-DD-HH-MM>

Prior: <prior-run-timestamp | none (first run)>
Toolchain: <tool version list>
Delta: +N new · N still open · N resolved

## What was found (plain English)
- **<id>** — <plain-English summary>. (<Severity>)

## What changed since last run
- <delta summary>

## Technical detail
| ID | Sev | File | Rule | Status |
|----|-----|------|------|--------|

Generated by MRPS Agent Launcher. Read-only. Findings are advisory.
```
