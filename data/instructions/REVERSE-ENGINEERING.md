# Reverse Engineering Instructions — MRPS Agent Toolkit

## Overview
Guidelines for inspecting compiled binaries, runtime application states, network telemetry, and disassembled bytecode.

## Category & Tools
- **Tools**: `rea` (`kind: mcp-server`)
- **Category**: `reverse-engineering`

## When to Reach for What
- Reach for `rea` (Reverse Engineer Anything) when analyzing compiled application bundles (Electron, native binaries, Android APKs, WebAssembly) or decompiling and reconstructing undocumented runtime APIs. Note: REA investigates named target artifacts; it does not scan repository roots for issue lists.

## The Inspect → Critique → Recommend → Fix Ladder
1. **Inspect**: Read binary headers, inspect exported symbols, dissemble procedures, and extract bundled metadata in read-only analysis sessions.
2. **Critique**: Identify undocumented dependencies, hidden communication channels, cryptographic weaknesses, or proprietary protocols.
3. **Recommend**: Document the reconstructed interfaces, type schemas, or security mitigations.
4. **Fix**: Never patch binaries automatically. Any patch or defensive adaptation must be written and approved in source code.

## Tool Guidance: REA
### When to use
Use when reverse engineering unfamiliar target executables, comparing bundle revisions, extracting assets, or tracing native UI behaviors.
### When NOT to use
Do not use for standard web source code audits or general source repository analysis where raw source code is already present.
### Example Invocation
```bash
npx rea-agents setup
# Connect agent to REA MCP server to inspect targets
```
