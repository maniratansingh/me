# Security Instructions — MRPS Agent Toolkit

## Overview
Guidelines for vulnerability assessment, static security auditing, dependency vulnerability scanning, and misconfiguration detection.

## Category & Tools
- **Tools**: `trivy` (`kind: cli`)
- **Category**: `security`

## When to Reach for What
- Reach for `trivy` to audit software bill of materials (SBOM), detect known CVEs in locked dependencies, locate hardcoded secrets, and flag misconfigured Dockerfiles or cloud templates.

## The Inspect → Critique → Recommend → Fix Ladder
1. **Inspect**: Execute static read-only vulnerability and secret scans over repository manifests and configs.
2. **Critique**: Assess CVSS scores, exploitability, patch availability, and real-world exposure risk.
3. **Recommend**: Suggest dependency version bumps or credential rotation steps without modifying manifest files.
4. **Fix**: Bump vulnerable dependencies in `package.json`, `requirements.txt`, or lockfiles only after the user explicitly authorizes the update.

## Tool Guidance: Trivy
### When to use
Use before pushing code, prior to release tags, or on schedule to monitor dependency vulnerabilities and container configurations.
### When NOT to use
Do not use for dynamic application penetration testing or live fuzzing against production infrastructure.
### Example Invocation
```bash
trivy fs --severity HIGH,CRITICAL .
```
